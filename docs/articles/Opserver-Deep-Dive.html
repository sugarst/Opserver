01

从一张报错页说起

The Configuration Problem

第一次把 Opserver 跑起来，浏览器里大概率是这个页面。很多人第一反应是「装坏了」，其实恰恰相反——这是它刻意设计的安全默认值。

opserverSettings.json 里没有 Security 配置节，SecurityManager.GetProvider() 就会落到 UnconfiguredProvider（IsConfigured = false），AuthController.Login 直接渲染 Views/Shared/NoConfiguration.cshtml；同时 HomeController 带着 [OnlyAllow(Roles.Authenticated)]，访问根路径一律 302 跳到 /login。

默认拒绝访问，是有意为之
源码里那句注释写得很直白："If people want read-all access...it should be explicit. Default is no access." 因为页面上的按钮是真的会改生产状态的，所以在没配鉴权、没配监控对象时，它拒绝给任何人看任何东西。截图里 TODO: Fix after merge 是上游模板的占位死链，跟配置错误无关。
02

它到底是什么

What It Is

Opserver 是 Stack Exchange 开源的监控系统，MIT 许可，仓库 StackExchange/Opserver。官方 readme 只有一句话定位："Opserver is a monitoring system originally from the team at Stack Exchange, home of Stack Overflow."

更准确的说法是统一运维监控 + 轻量处置面板。它把各类中间件的当前健康状态聚到一套 ASP.NET Core Web UI 里，供值班工程师快速判断现状、顺手处理。它没有时序数据库、不存历史曲线、不让你写查询语句——更像叠在现有组件上方的一块实时控制台。

它回答的问题
「现在哪个实例不健康？」「这条慢查询的执行计划长什么样？」「把这个 Redis 节点提成主库。」
它不回答的问题
「过去 30 天 CPU 的趋势如何？」「下个季度该扩容多少？」「帮我配一条 Prometheus 告警规则。」
03

五层架构与三个取舍

Architecture
  • 配置层：Program.cs 依次加载 appSettings.json、一批 Config/*Settings.json 兼容文件、opserverSettings.json，最后加载被 gitignore 的 localSettings.json（专门用于本地覆盖）。
  • 采集层：PollingService 是一个 IHostedService，起一条低优先级后台线程，按 PollNode 树周期性拉取状态，结果写入 IMemoryCache。
  • 组织层：StatusModule 子类各管一类系统。StatusModule.cs 的 AddStatusModules() 用反射扫描程序集、注册全部非抽象子类——加新模块不用改注册代码。
  • 呈现层：Razor 视图 + 大量 JSON 端点 + /hub 聚合页，配合模块级角色鉴权。
  • 使用层：NavTab.ConfigureAll() 反射找控制器上的 [DefaultRoute]，只为已启用的模块生成顶部 Tab。
取舍一 · 没有自己的数据库
轮询结果只留在进程内存里，重启即重新拉取。部署极轻，代价是没有历史趋势可查。
取舍二 · 一切由配置驱动
Modules:* 下配了数据源，模块才算 Enabled；仓库自带配置把各模块示例全注释了，默认一个都不开。
取舍三 · 权限颗粒度到模块
EveryonesReadOnly / EveryonesAnAdmin 是两种极端 Provider，生产可用 AD 或 OIDC，再叠加每个模块的 ViewGroups / AdminGroups。
附带效果 · 导航自动生成
配置里少一个模块，界面上就少一个 Tab。这也是为什么只配 Redis 时，顶部只有孤零零一个入口。

05

能动手，不只是能看

Read And Act

绝大多数监控面板是只读的，Opserver 不是。每个模块都有 *.Admin.cs，端点带 [OnlyAllow(...Roles.Admin)]：Redis 能 kill 客户端、切主从、清 Key；SQL 能移除执行计划、启停 Agent Job；HAProxy 能启停后端；PagerDuty 能改事件状态；Exceptions 能删除异常并联 Jira。

这些动作统一受 SecurityManager + Roles（Anonymous / Authenticated / LocalRequest / InternalRequest / ApiRequest / GlobalAdmin / GlobalViewer）+ 模块级 ViewGroups / AdminGroups 约束，把「能看」和「能动手」分开。这也解释了为什么默认拒绝访问是合理的设计：一旦放开，页面上的按钮是真会改生产状态的。

06

和 Grafana 怎么分工

Positioning
维度OpserverPrometheus + Grafana
定位实时状态 + 运维操作台长期时序 + 图表 + 告警规则
数据存储无独立库，轮询结果在进程内存时序数据库，保留历史
面板来源代码内置，配置即启用自己写 PromQL / 配面板
取数方式主动轮询各系统原生接口exporter 暴露指标后被拉取
能否处置能，切主从 / 停 Job / 清计划基本只读
适合场景值班排障、常见操作固化趋势分析、容量规划、告警体系

结论不是「谁替代谁」，而是层次不同：Opserver 是给工程师当场处理问题用的，Grafana 是给团队长期观察系统用的。

07

本地跑起来

Run It Locally
cd src/Opserver.Web
dotnet run --launch-profile "Opserver.Web"

默认监听 http://localhost:56058/（Properties/launchSettings.json，Development 环境）。只跑这一条命令，看到的就是图 1 那张报错页。想看到真实界面，新建一个本地专属的 localSettings.json（已被 .gitignore 忽略）：

{
  "Security": { "Provider": "EveryonesAnAdmin" },
  "Modules": {
    "Redis": {
      "Servers": [
        { "Name": "localhost", "Instances": [ { "Name": "Default", "Port": 6379 } ] }
      ]
    }
  }
}

重启后登录页变成只填用户名（EveryonesAnAdmin 的 FlowType 是 Username，无密码），首页自动跳到 /redis。

1 Chained Instance 前的绿点代表 MonitorStatus: Good；表中 Default 是实例名，主机 localhost:6379，角色 Master，0 副本，436 Ops/sec，7.75MB 内存，2 个客户端，9s ago 是轮询缓存的新鲜度。下半部分留白只是因为只配了一个实例。

安全提醒
EveryonesAnAdmin 意味着任意用户名都能拿到全站管理员权限，仅限本地开发。这个文件不能进版本库，更不能出现在生产或公网；生产请改用 ActiveDirectory 或 OIDC。删掉它就恢复默认拒绝访问。
08

升级到 .NET 10 的记录

The Upgrade

上游 Opserver 长期停留在 .NET 8。当前这个 fork 在 feature/upgrade-net10 分支完成了一轮「功能不变、只换运行时和依赖」的升级：

运行时与工程文件
net8.0 → net10.0；.sln → .slnx 并删除旧解决方案；Dockerfile、GitHub Actions、AppVeyor 同步升级。
两处废弃 API
Program.cs 改用 Host.CreateDefaultBuilder + ConfigureWebHostDefaults（ASPDEPR008）；Startup.cs 改用 KnownIPNetworks + System.Net.IPNetwork（ASPDEPR005），但保留 KnownNetworks 配置键兼容既有部署。两者都在 TreatWarningsAsErrors=true 下直接变编译错误。
Jil 反序列化必崩
.NET 9+ 新增 TimeSpan.FromSeconds(long) 重载，Jil 2.17.0 反射取方法时抛 AmbiguousMatchException。把源码内置到 vendor/Jil，按精确签名 FromSeconds(double) 改一行，业务代码零改动。
SQL 驱动迁移
System.Data.SqlClient → Microsoft.Data.SqlClient 6.1.8（支持到 2028-08 的 LTS）。新驱动 4.0+ 默认 Encrypt=true，用 Connection.WithLegacyEncryptionDefault() 补回 Encrypt=False 保持旧连接语义；连带把 StackExchange.Exceptional 从 2.2.35 升到 3.0.1，去掉运行时对旧驱动的硬引用。
Redis 3.x 的两个破坏点
SocketManager 被移除（删字段）；随包 analyzer 报 SER308 sync-over-async（在 server.Wait(last) 单点豁免并记录原因）。3.x 默认 RESP3，已在 Redis 6.2 上实测握手与轮询正常。
测试与可观测性
xunit 2.9.3 → xunit.v3.mtp-off 4.0.2（迁移 v3 但保留 VSTest）、coverlet.collector 10.1.0、MiniProfiler 4.5.8、Dapper 2.1.89、SourceLink 10.0.403。
验收
dotnet build 零警告零错误、dotnet test 97/97 通过、Release 发布成功，再辅以启动 / HTTP / Jil 序列化 / SQL 连接四处冒烟。
09

适合谁，不适合谁

Fit And Non-Fit
适合
已经在用 SQL Server + Redis + Elastic + HAProxy 这类自建中间件；值班时需要快速判断并处置；不想为每个系统单独开后台；希望「查看」和「操作」收在同一套权限体系下。
不适合
需要长期历史趋势、容量规划、自定义告警规则、多租户或大规模指标量。这些应该交给 Prometheus / Grafana / OpenTelemetry 体系——Opserver 不存历史，也不做告警计算。
10

结语

Closing

Opserver 是个很有 Stack Overflow 气质的项目：不追求通用，不堆抽象，直接把自己机房里每天要用的排障动作做成了页面；默认拒绝一切访问、权限分到模块、轮询只放内存——每一处取舍都透着「给自己运维同事用」的实用主义。

它也不是一个可以照搬的现代项目：Razor + jQuery 的老前端、部分 TODO 占位、对 .NET 8 的长期停留都还在。但正因如此，把它升级到 .NET 10 的过程反而成了很好的一次架构阅读——你能清楚看到哪些是设计、哪些是历史包袱，以及升级一个真实项目时，编译错误往往只是最容易的那一层。
